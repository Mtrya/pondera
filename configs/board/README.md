# Board representation comparison

Compare the fixed-depth base model before transferring a board representation to adaptive backbones. Run `absolute.toml` and `relative.toml` once each with the same seed and dataset. The absolute model has 4,023,730 trainable parameters; reducing the relative model's FFN width to 766 gives 4,024,786 parameters, a residual difference of 0.0263%. All other settings and action supervision are shared. Select geometry provisionally using final held-out cross-entropy, with top-1 accuracy as an additional diagnostic. Then copy the selected configuration and change only `model.layout` to `"pieces"` for one compact-piece run. This is a staged comparison, not a full layout-by-geometry grid.

Each run receives 5 × 10^15 theoretical training dense-matmul FLOPs. The trainer accounts for each example's logical token length, so compact inputs may consume more examples at the same budget. The final optimizer step can overshoot the budget by less than one optimizer batch; record the actual total. Parameter count and theoretical FLOPs are the alignment criteria. Runtime, throughput, and memory are engineering diagnostics only. One seed is an exploratory screen, not evidence of robustness across initializations.

Use a common lossless dataset built from the `stockfish_train` and `stockfish_val` splits of `kaupane/chess-positions`, revision `9321f3749806972a29307ea37a975c6bdcca757d`. Preserve raw FEN counters and use repetition 1 when history is absent. Treat a position key as the first four FEN fields. Keep the full 67,866-row validation split. Sample 1,500,000 evenly spaced rows across the ordered training shards; remove validation position keys and retain the first occurrence of each remaining training key; then select 1,000,000 evenly spaced eligible rows. Train examples have equal weight; the source frequency column does not change the sampling weight. Store source selection details and encoded-array checksums with the dataset.

The trainer uses AdamW, effective batch size 512, BF16, and a warmup/cosine learning-rate schedule indexed by consumed theoretical FLOPs. Ten epochs are a ceiling; verify that the FLOP budget is reached. Validation and checkpointing occur every 500 optimizer steps and at completion. The value projection retains the common policy interface but receives no value loss. Final cross-entropy and top-1 accuracy concern the supplied best-move labels, not a claim of measured playing strength.
