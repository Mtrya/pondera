# Model inference

`trace.py` loads the checkpoint's architecture, weights, and merge dictionary, then uses the model's cached forward method. Generation prefills the board and decodes one new token per step. Each request owns its caches. Forcing FINAL after the reasoning budget or replacing an invalid reasoning prefix prefills the resulting context again. The model with chess-path reads resolves composite tokens through the checkpoint dictionary and caches the earlier layer outputs reachable from its current path. The predictor passes the available host tokens to this model during decoding.

A reasoning budget counts model calls before `FINAL`. Natural `FINAL` starts the answer early; reaching the reasoning limit inserts `FINAL` without a model call. A zero budget prefills `FINAL`. The separate answer allowance counts model tokens after that delimiter. Answer generation is greedy and unconstrained: no field, move, value, PV, or `END` is repaired or masked. A premature `END` or exhausted answer budget produces a failed answer.

`parse_answer` expands dictionary tokens into base atoms before interpreting the suffix. Equivalent segmentations, including composites crossing answer-field boundaries, produce identical parsed answers. The prefix before `FINAL` is opaque. A complete suffix contains a decision, a value, optional mate information, zero or more continuation moves, and `END`. PV continuation excludes the already-selected decision. Moves are interpreted in the root player's token frame and replayed in absolute coordinates; legal draw claims require the supplied repetition count or halfmove clock. Format validity, decision legality, PV legality, and failure codes remain separate.

`vanilla_uci.py` defaults to the legal-masked, zero-presentation policy. With `--reasoning-tokens`, it uses the same greedy reasoning prefix as the checkpoint evaluator and masks the decision after FINAL to legal root moves. If generation ends before a decision context is available, it plays from the board followed by FINAL. `uci.py` owns the UCI protocol.

`load_checkpoint` and the UCI entry accept a positive `loop_repetitions` / `--loop-repetitions` override when the model specifies exactly one segment with an explicit `repeat`. This changes the number of executions while retaining the same weights. Evaluation metadata records the executed repetitions for each segment.
