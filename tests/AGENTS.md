# 测试规范

写或修改 `tests/` 下任何测试前必读。

## 核心原则：两个独立来源相互印证

每个测试必须存在两个独立来源的结论彼此吻合：被测实现是一个源，期望值必须来自另一个源。在测试里用与被测代码相同的逻辑重算期望，是重复实现，不是测试——它把同一份逻辑维护两遍，且对真实 bug 不敏感（两边会一起错）。

合法的第二源只有四类：

1. **外部独立实现**：如 python-chess 的合法走法生成、FEN 解析。我们的实现与它们互不知情，吻合才有信息量。
2. **解析推导的常数**：手工推导一次、冻结为字面量的期望值（如对微小 logits 手算的交叉熵、对微小配置手算的 FLOPs）。推导依据用一句话写在注释里；不允许在测试运行时按同一公式重算。
3. **冻结契约**：manifest schema、checkpoint 格式版本、数据数组 layout、UCI 协议行为——期望值来自契约本身，而非来自当前实现。
4. **不变量**：无损往返（encode→decode 恢复原输入）、因果掩码（未来注意力为零）、概率归一、resume 连续性（同配置中断重训的 loss 序列吻合）。断言的是性质，不是中间计算结果。

对纯数学函数，另一个独立实现（如 `torch.nn.functional.cross_entropy`）也算第二源。

## Litmus

- "这个测试的期望值是从哪来的？"——答不出，或答案是"照被测代码抄一遍"：删。
- "对被测函数做一次等价重构，这个测试还会过吗？"——如果不会，说明测的是实现细节而非行为契约：改或删。

## 其他规则

- 测可观察行为与数据契约；不给入口参数解析、常量表、纯转发函数写测试。
- 使用真实实现与本地 fixture（临时目录里的小规模真实数据），不 mock。
- 不冻结散文、日志措辞或偶然目录结构，除非确切措辞就是契约。
- 依赖外部可执行文件（stockfish、fastchess）的集成测试按存在性 skipUnless；它们在本机会真实执行，必须保持能通过。
- 删除代码时连同其测试一起删；退役实现的测试不"保留作纪念"。
- 测试数量不为目标服务：没有第二源的测试是负资产。
