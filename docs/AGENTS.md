# docs/ 与公开内容规范

写或修改 `docs/` 下任何文档前必读。

## docs/ 里有什么

- 自足、适合公开读者的文档：模块边界（architecture.md）、当前数据合成管线（data.md）、已收敛研究结论（research/）。
- 不收录：进行中的工作、session 笔记、机器特定说明、内部术语与指代。这些属于本地研究层（`.local/research/`），不入 git。

## 写作标准

- 自足：外部读者不依赖任何仓库外的上下文即可理解；不把解释责任推卸给不可见的指代（内部代号、session 计划、本地路径）。
- 稳定：只写已定型的事实；进行中的实验协议与未决问题不进 docs/。
- 可公开：无凭据、无机器隐私、无黑话。被 git 追踪不等于可以公开；公开标准同样适用于代码、注释、配置、测试与 PR。

## docs/research/ 的晋升标准

research/ 只收录已收敛的研究问题，一页一问：问题 → 选项 → 证据 → 结论 → 指向公开产物（leaderboard、代码、配置）的指针。

晋升前提（缺一不可）：

- 结论由负责任的实验得出：对照与所问问题相关的对齐维度声明清楚（如参数量、数据 identity、样本呈现次数、优化步数与 LR 进度），不制造虚假相等，不凭显著更多的训练曝光淘汰候选；FLOPs 可作为实验设计与训练规划的参考，但不是必须对齐的维度，也不应成为训练时的控制量；
- 观察、机制假设与证据三分落实，关键解释经过探针或针对性小实验验证；
- 必要的规模依赖已检查——小规模赢家不等于扩展潜力赢家；
- 页面自足且公开可读。

结论 settle 后立刻晋升；晋升后本地 thread 删除或留一行指针。晋升的操作流程与本地研究层结构见 `.local/research/AGENTS.md`（本地文件，不入 git）。
