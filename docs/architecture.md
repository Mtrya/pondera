# Repository architecture

Pondera is an installable Python package rooted at `src/pondera`. It is a library: training, trace data preparation, and UCI serving expose `python -m` entry points, and experiment orchestration lives in run directories outside the package. Imports do not start engines, download checkpoints, or create outputs.

| Location | Responsibility |
|---|---|
| `chess/` | Action vocabulary, rule-only path tracking, lossless board token encoding, exact symmetry transforms, and min-cost merge dictionaries |
| `models/` | Neural model definitions |
| `data/` | Root preparation, trace curation, and vocabulary fitting plus encoding under one TOML recipe; release validation, authoritative text conversion, and packed training datasets |
| `tools/export_hf.py` | Bounded projection of an accepted local release into the shared eleven-column Hugging Face dataset; schema definitions remain in `data/` |
| `training/` | TOML training recipes, supervised optimization, and resumable training state |
| `inference/` | Checkpoint loading, generic autoregressive generation, expanded-answer parsing, legal move selection, and UCI |
| `evaluation/` | Full-document checkpoint loss, evaluation on roots and puzzles, cached engine references, external matches, and opening assets |
| `tests/` | Behavioral and integration tests |
| `results/` | Reviewed summaries of completed evaluations |

Representation code does not import application layers, and models do not import workflows. Training and inference use the model definitions. Encoding writes final memory maps directly from authoritative text, using one shared trace-boundary rule for fitting and encoding. Training selects a seeded document prefix under a configurable length cap from the stored lengths. Training reads these packed datasets and dataset identity checks from `data`; it does not call collection, synthesis, search, or evaluation code. Evaluation orchestrates inference and external engines. Data and evaluation do not import training. Import contracts enforce these boundaries.

The board tokenizer has one format shared by offline data preparation and runtime inputs: sparse self-contained `(square, piece)` atoms plus metadata atoms, preserving piece placement and the first four FEN fields exactly. Base token IDs and names are generated directly from the arithmetic layout in `chess/vocabulary.py`. The fullmove counter is not encoded; halfmove clocks of 100 and above and repetition counts above four share their respective top atoms.

Both policy baselines are fixed-depth causal Transformers over one packed token stream, with NoPE, pre-norm RMSNorm, SiTU-GLU feed-forward networks, and grouped-query attention. The vanilla model uses causal softmax attention. The linear-attention model uses an identity feature map, no decay and unnormalized readout, with fp32 chunk and recurrent states. Model configuration contains dimensions and vocabulary size; the checkpoint's `arch` field selects the implementation.

The `gdn` and `kda` models use Gated DeltaNet and Kimi Delta Attention, respectively: causal four-token depthwise convolutions, L2-normalized queries and keys, residual memory writes, learned decay, and gated per-head normalization. GDN decays each head; KDA decays individual key channels. `[model].softmax_every` places causal softmax attention at that layer interval; zero selects a pure delta model. Delta layers use `num_heads` full memory heads, while `num_kv_heads` controls hybrid softmax layers and must equal `num_heads` in a pure delta model. Convolution and memory state reset at document boundaries and are retained together during incremental decoding. CPU execution uses the fp32 recurrence; accelerator execution requires [FLA kernels installed for the target backend](https://github.com/fla-org/flash-linear-attention/blob/main/INSTALL.md). Sequence metadata is prepared once per attention type in each forward pass.

In `kda_token_value`, the last softmax layer projects keys and queries from its current input and values from the original token embeddings. `kda_token_value_block_attn_res` adds per-token attention over groups of earlier residual updates. `kda_token_value_navigation` uses the visible `BACK` and `RESET` atoms to locate a branch predecessor after the fourth block. A learned query mixes the current state, that predecessor and the latest move state. `kda_token_value_block_attn_res_navigation` combines the two reads. Packed training resets the branch stack at document boundaries, and incremental decoding keeps earlier states for the root, the active path and the latest move until `FINAL`.

The `kdn` architecture implements isotropic [Kalman Delta Networks](https://arxiv.org/abs/2609.07816): one uncertainty scalar per head controls writes into the full associative memory. Learned process and observation noise update covariance through a packed Möbius scan, with independent learned priors at document boundaries. The information scale is fixed to the key dimension, making the scalar write coefficient equal to posterior covariance divided by observation noise. Channel decay, normalized Q/K, short convolutions and a sigmoid output gate follow the isotropic model. Cached decoding retains covariance, associative memory and convolution histories. GDN, KDA and KDN share the delta-rule execution backend; differentiable calls use chunk kernels even when they receive an initial memory, while inference can use recurrent kernels.

The `gdn2` architecture implements [Gated DeltaNet-2](https://arxiv.org/abs/2605.22791): independent channel-wise erase and write gates extend KDA's memory update. The author's `beta_guard` contracts erase-channel contrast when required by its decay-dependent stability condition, rechecks quantization, and uses a straight-through erase gradient. Training and decoding both project using the per-token decay. The model retains short convolutions, normalized Q/K, channel decay and hybrid softmax layers, with a SiLU output gate. Accelerator execution maps the update to FLA's diagonal-plus-rank-one kernels; CPU execution uses the same memory recurrence. Incremental decoding retains memory and convolution histories together.

The `cyfa` architecture implements [Cyclic Flow Attention](https://arxiv.org/abs/2609.36259) with separate key and value memories, a learned cyclic clock, and a softmax readout in a real Fourier basis. It uses linear short convolutions, learned Q/K RMS normalization and a sigmoid output gate. `num_slots` is the even storage width, including one unused Fourier component. `softmax_every` has the same meaning as in the delta models. Packed documents reset both memories, clock and convolution histories; incremental decoding retains all four. The clock accumulates fixed-point integer increments to keep long parallel and cached computations consistent. Ascend batches independent bounded segments and computes initial and terminal scalar-memory contributions separately in fp32, propagating state and gradients across segments while preserving complete-document context. Shared convolution and cache handling lives in `models/memory.py`.

The looped model reuses vanilla blocks, keeping two blocks before and after a shared middle stack. Training selects a common repetition count for each optimizer update from its seed and update number; inference uses the configured repetition count or an explicit override. Each execution of a shared block has its own incremental attention cache. The `recurrent` architecture uses the same shared-core layout and depth sampling, starts from a zero state, adds the prelude representation at every iteration, and applies RMS normalization after each residual sublayer and core iteration. This implements the additive small-model variant motivated by [recurrent depth](https://arxiv.org/abs/2502.05171); cached execution retains separate attention histories for every core execution.

For `looped` and `recurrent`, `mixer` selects `softmax` (default), `gdn`, or `kda`. With a delta mixer, `softmax_every` inserts full-attention layers at the same physical intervals as the non-looped hybrid. Every execution retains its own attention state and short-convolution history during generation, including repeated uses of a shared block. At one repetition, the plain looped model has the same initialization and computation as its non-looped counterpart.

The plain `looped` architecture optionally sets `scale_residuals = true` to multiply each attention and FFN residual branch in the shared core by the inverse of the actual repetition count. Prelude and coda blocks keep unit scale. Training uses its sampled count and inference uses its requested count, with the same scaling in full and cached execution. This controls accumulation across shared iterations without adding parameters; it does not implement the full initialization and optimizer parameterization of [Loop-μP](https://arxiv.org/abs/2606.18524).

For looped models with input injection, `[training].backprop_repetitions` optionally limits backpropagation to the final iterations of the sampled depth. Earlier iterations run at the same precision without retaining their computation graphs. The prelude still receives gradients through its injection into later iterations. This also applies to `recurrent`; evaluation and cached generation always execute the requested full depth.

For `looped`, `input_injection = "decay"` learns a diagonal carry and an identity-initialized projection of the fixed prelude into each core iteration. `"orthogonal"` adds [OrthoInj](https://arxiv.org/abs/2610.06833), removing the carry component along that projected input before adding it. Both start from a zero recurrent state, retain the original pre-norm blocks, and initialize the per-channel step to half the logarithm of five and the decay rate to one. The fixed input projection is computed once per forward pass; projection inner products use fp32 under mixed precision. Each core execution still owns its temporal memory and convolution cache.

For a plain `looped` delta model, `kv_replay = true` implements Full Replay from the [Historical KV Replay talk recap](https://jinyansu1.github.io/blog/2026/10/looped-lm-recap-1-lt2/). At each token, each core delta layer decays its own loop's memory once, writes the current loop's K/V, then replays earlier loops' K/V in reverse order using their originating write strengths. The current query reads after the final write. Each token expands into consecutive delta updates, with document boundaries expanded accordingly; short convolutions operate on the original token sequence. Earlier-loop projections remain differentiable across activation recomputation. Generation retains separate temporal memory and convolution histories per loop, reusing projections only for the current token. Replay adds no parameters; the number of writes per core layer grows from n to n(n+1)/2 for n loops.

For `looped`, `attention_residual_decay` enables [InfiLoop's attention residual](https://arxiv.org/abs/2610.11570) over core outputs and sets its initial learned decay between zero and one. A shared query scores each token's RMS-normalized state; scores are clamped to [-8, 8]. The initial state and successive core outputs enter a running weighted numerator and denominator, with earlier weights decaying at each iteration. Their ratio becomes the next recurrent state. Scores and accumulators use fp32 under mixed precision, and the mechanism adds hidden_size + 1 parameters. Aggregation is local to each token and needs a constant amount of state across depth; each attention execution still retains its own temporal cache. This single-axis mechanism uses Pondera's causal model and existing next-token objective.

The `board_context` and `symbolic_board` architectures condition query/key channel scales on the root-board prefix already visible to each token. A cumulative prefix summary remains fixed after the first trace token. The learned version sums learned atom features; the symbolic version uses frozen embedding, affine and ReLU weights to compute piece counts and attack counts, including slider blocking. Both preserve causal prefix predictions and maintain the summary alongside attention caches. The symbolic circuit performs no move expansion or search, and its frozen weights are included in parameter counts. Optimizers exclude frozen parameters and assign all learned embedding tables to AdamW.

Board conditioning supports `mixer = "softmax"`, `"gdn"`, or `"kda"`; delta mixers use `softmax_every` for hybrid layers. The conditioning branch uses `context_rank` channels, capped at the model width. Delta Q/K modulation follows the short convolution and precedes L2 normalization, preserving normalized memory writes. The complete backbone is initialized before conditioning branches, so its initial weights match the corresponding unconditioned model at the same seed. Full and incremental execution share the projection and memory rules; each attention cache retains the underlying softmax or delta state.

Training reads `[model]` and `[training]` from `configs/train.toml` through `training/config.py`; `training/packed.py` owns the entry point, batching, and training state, and `training/muon.py` owns optimizer construction. Architecture, dimensions, document selection, optimization, token budgets, stopping targets, seed, validation frequency, checkpoint frequency, and retention are recipe settings. Vocabulary size comes from the encoded dataset. Dataset/output/resume paths, device selection, and telemetry enablement are command arguments. Resume uses the requested recipe and validates it against the checkpoint rather than replacing requested model settings.

`muon_lr` and `adamw_lr` are peak learning rates. Both optimizers use linear warmup over `warmup_fraction` of the training budget (default 0.05), followed by cosine decay to `min_lr_ratio` times their peaks (default 0.1). Progress is the fraction completed by the upcoming update: optimizer updates when `updates` is set, otherwise consumed documents toward the presentation target. The final update uses the minimum rate, including when its batch is short. Actual `muon_lr` and `adamw_lr` values are recorded in the local history and telemetry. Resume derives the next rate from saved progress and the requested recipe; extending the stopping budget stretches the schedule over that new budget.

`[training].hyperball` applies the [Hyperball update](https://arxiv.org/abs/2606.16899) to Muon's hidden matrices. It normalizes each update to the matrix's initial Frobenius norm and projects the updated matrix back to that radius. The model keeps its usual initialization; `muon_lr` controls the relative update length. Embeddings, output heads and normalization gains retain AdamW. `weight_decay` applies only to AdamW when Hyperball is enabled. The radius is saved in optimizer state, and resume requires the same Hyperball setting.

`max_presented_documents`, also exposed as `--max-presented-documents`, adds an absolute document-presentation ceiling independent of the optimization schedule. Training stops when either its recipe target or this ceiling is reached. Short final batches preserve whole documents. `progress.json` atomically reserves each upcoming global update's cumulative document count before model computation, allowing external orchestration to account conservatively for interrupted work. The history records per-update tokens, cumulative documents, elapsed training time, and validation duration.

Training prepares sequence metadata on the host once per forward. Softmax attention reuses the maximum document length in every layer. Linear attention batches independent documents in groups rounded to powers of two chunks, keeping each document's state separate; padding is internal to the attention computation. Distributed updates plan global batch indices from length metadata, read only each rank's tokens, and reduce accumulated gradients once per optimizer update.

On Ascend, causal half-precision attention uses the fused TND kernel with host sequence boundaries and a shared compressed causal mask. Calls split at document boundaries to bound the operator's batch size while preserving training batches.

The default training recipe enables `activation_checkpointing`: each block is recomputed during backward to reduce memory use on long documents.

`[training].objective` selects `all_tokens` (the default next-token loss) or `final_decision` (only the label immediately after an input `FINAL` token). Both objectives forward the same packed documents and retain the same token-based update budget. `decision_loss_weight` adds a weighted mean final-decision loss to the all-token training objective. Losses and accumulated gradients are normalized across microbatches and distributed ranks. A batch or idle rank with no selected labels contributes zero gradient; an entire update with no selected labels raises an error. Resume requires matching training objectives and decision weights. Validation always uses uniform next-token loss over every complete validation document, independent of training selection and objective; `val_labeled_tokens` reports its full label count. The standalone `pondera.evaluation.loss` entry uses the same metric and retains per-document sums for paired comparisons.

Packed-trainer checkpoints use `format_version = 3` and retain model and optimizer states, the actual number of presented traces, dataset identity, tokenizer versions and merge entries, selected document indices, training configuration, and the SwanLab run ID. Resume requires the same architecture, model dimensions, dataset, tokenizer, selected documents, sampling seed, and microbatch token budget. The consumed-document count locates the next document in the selected epoch order. A longer presentation target continues this order even after a partial final batch; same-configuration resume at an optimizer boundary reproduces uninterrupted training. Requested learning rates and weight decay override the saved optimizer settings. Local `config.json` and SwanLab share the same configuration, including architecture; `history.jsonl` is the local training history, and resume discards records beyond the loaded checkpoint before appending.

Checkpoints are written atomically as `checkpoint-00000050.pth`, with the optimizer update in the filename. `checkpoint.pth` is a relative symlink to the latest snapshot, sharing its storage. `[training].checkpoint_keep_last` defaults to three and must be positive. After publishing a new snapshot and updating the latest link, the trainer removes older numbered snapshots beyond the retention limit. Resuming from an older update into the same run directory also removes snapshots beyond the resumed history after the next successful save. Final saves use the same retention policy, including when periodic checkpointing is disabled.

`python -m pondera.evaluation` reads `configs/eval.toml` and evaluates the same selected held-out roots or puzzles with zero reasoning and a configured thinking budget. `inference/trace.py` generates through the common autoregressive model interface and parses expanded atoms, accepting equivalent token segmentations. Reasoning may end naturally with FINAL or be truncated by inserting FINAL at its model-token limit. Answer generation has its own allowance and remains unconstrained; END is never forced. The reasoning prefix is opaque, while suffix format, decision legality, and PV legality are checked independently. Invalid or incomplete answers remain failures. Evaluation caches fixed-budget Stockfish scores outside inference and reports move quality, root-value accuracy, PV quality, and puzzle success with explicit coverage. It writes aggregate and per-position results without importing training or logging telemetry.

Generation reuses the board encoding, appends a standalone `FINAL`, masks the next-token distribution to legal decisions, and returns the highest-scoring move. Black move scores use the reflected move IDs used in training; the board prefix and returned UCI move remain in absolute coordinates. The UCI protocol loop is independent of checkpoint loading and move selection; `pondera.inference.vanilla_uci` serves these checkpoints, preserves repetition counts from the supplied move history, returns `0000` for finished games, and is the default match engine.

## Repository hygiene

Maintain reusable code inside the package. Do not add root Python scripts or generic utility packages. Temporary scripts, downloaded data, checkpoints, logs, external tools, and research working notes use `.local/scratch`, `.local/data`, `.local/runs`, `.local/research`, and `.local/tools`, or explicitly selected external storage. Run directories contain their configuration and outputs; evaluation does not automatically modify reviewed result summaries. Shared data and training recipes live in `configs/`. Experiment configurations live with their run directories; only published reference runs add experiment configurations to the repository.

Research records have two layers. Working notes — the experiment ledger, open research threads, and session handoff — live untracked under `.local/research/`. Converged, publicly readable conclusions are promoted to `docs/research/`. Everything else in `docs/` is stable, self-contained, and appropriate for public readers. Ignore rules use explicit exclusions. Being visible to Git is not approval to publish a document. The same public-content standard applies to code, comments, configurations, tests, and pull requests: no references to session-specific plans or unavailable internal material.

Retire unused implementations after checking their callers and required baseline behavior. Git history retains previous implementations. Add tests for observable behavior and data contracts, using actual implementations and local fixtures; do not encode prose or incidental directory structure as tests.
